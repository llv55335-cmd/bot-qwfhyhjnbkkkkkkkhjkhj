> 最后更新：2026-05-06

---

## 项目定位

Qingqing 是一个统一的 Python 后端，服务于 AI 伴侣 **Cael**。它合并了两个原本分散的子系统：

- **mew/** —— 飞书 AI bot（AI 大脑、记忆引擎、飞书消息处理、工具调用）
- **server.py** —— 独立 Flask 服务（文件读写、网页抓取、Polly 控制、论坛收件箱）

技术栈：**FastAPI + Uvicorn + SQLite + sqlite-vec + sentence-transformers**

## 分层架构

```
┌─────────────────────────────────────┐
│              飞书 / HTTP              │  ← 外部
├─────────────────────────────────────┤
│  adapters/  (HTTP 路由)              │  ← 适配器层
│  ports/     (飞书 WS 消息)           │
├─────────────────────────────────────┤
│  core/      (AI 大脑 + 工具分发)     │  ← 核心层
├─────────────────────────────────────┤
│  services/  (业务逻辑)               │  ← 服务层
│  tools/     (工具实现)               │
│  memory/    (记忆系统)               │
│  time_tools/(时间工具)               │
├─────────────────────────────────────┤
│  config.py  (配置)                   │  ← 基础设施
│  data/      (SQLite 数据库)          │
└─────────────────────────────────────┘
```

**依赖方向**：上层依赖下层，下层不依赖上层。`core/` 是中枢，连接所有模块。

## 数据流

### 飞书对话流程
```
飞书消息
  → ports/feishu.py (handle_message)
    → core/ai_core.py (call_ai)
      → memory/retrieve.py (检索相关记忆)
      → tools/  (工具调用，含 memory_tools)
      → OpenRouter API (LLM 推理)
    → core/conversation_summarizer.py (对话总结 + 自动写记忆)
  → ports/feishu.py (发送回复)
```

### HTTP 请求流程
```
HTTP 请求
  → adapters/http_xxx.py (路由)
    → services/xxx.py (业务逻辑)
      → 文件系统 / 网络 / Polly
  → JSON 响应
```

### 记忆生命周期
```
1. 写入: ingest_initial.py 或 conversation_summarizer 或飞书对话自动识别
   → memory/ingest.py → memory/graph_store.py (SQLite)
2. 检索: core/ai_core.py 每轮对话前
   → memory/retrieve.py (触发条件匹配) → graph_store.query
3. 维护: memory/maintenance.py 每周清理/去重/调整重要性
```

## 数据库表结构 (graph_memory.db)

| 表名 | 用途 | 关键字段 |
|---|---|---|
| nodes | 节点（用户、记忆实体） | uuid, label, type |
| edges | 边（节点间关系） | id, source_uuid, target_uuid, relation |
| memories | 记忆内容 | id, node_uuid, content, summary, importance(1-5), auto_ingested, decay_score, status |
| paths | 记忆路径（文件映射） | domain, path, edge_id, context(JSON) |
| snapshots | 对话快照 | id, content, created_at |
| co_occurrence | 共现统计 | memory_id_a, memory_id_b, count |
| vec_memories* | 向量索引（sqlite-vec） | embedding 分块存储 |

**2026-05 新增字段**：
- `memories.auto_ingested` (INTEGER) — 0=手动导入, 1=AI 自动生成
- `paths.context` (TEXT) — JSON 数组，记录 context 标签

## 已知问题

| 问题 | 影响 | 状态 |
|---|---|---|
| Windows GBK 不支持 emoji 输出 | print/日志中的 emoji 会报 UnicodeEncodeError | ✅ 已修复（改用 log.info/warning） |

### 已修复 (2026-05-06)

| 问题 | 影响 | 修复方式 |
|---|---|---|
| PyTorch DLL 加载路径错误 (`D:bin`) | embedding 模型无法加载，记忆检索降级为纯文本匹配 | `app.py` 顶部在 `from __future__` 之后加了 `sys.exec_prefix` 修复 hack |
| FOREIGN KEY constraint failed (ingest 写 paths) | `paths.edge_id` 错误引用 `memories.id` 而非 `edges.id`，导致 paths 写入失败 | `ingest.py` `_store_memory()` 先调用 `add_edge()` 拿 `edge_id`，再传 `add_or_replace_path(edge_id=...)` |

## 启动命令

```bash
cd qingqing

# 1. 配置
cp .env.example .env
# 编辑 .env，至少填 TOKEN1 和 HOME_KEY

# 2. 装依赖
pip install -r requirements.txt

# 3. 仅 HTTP（关闭飞书）
FEISHU_ENABLED=false python app.py

# 4. 完整启动（HTTP + 飞书 bot）
FEISHU_ENABLED=true python app.py

# 5. 一次性导入记忆
python scripts/ingest_initial.py --dry-run  # 预览
python scripts/ingest_initial.py            # 正式导入
